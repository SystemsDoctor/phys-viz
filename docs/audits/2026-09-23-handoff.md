## Process notes for whoever picks this up

- One commit per X-id (or per closely-related decision-item), each
  with: the fix, a golden test that FAILS against the pre-fix code and
  PASSES against the fix (verify this explicitly — `git stash` the fix
  files, rerun the new tests, confirm they fail, `git stash pop`), the
  full local verification sweep (`typecheck`, `lint`, `test:unit`,
  `test:contract`, `build`, `check:budget`, `format:check`), a targeted
  `npx playwright test tests/e2e/smoke.spec.ts -g "<name>"` run for
  anything renderable, and a TASKS.md `[DONE]` flip with a terse
  "Verified:" note (what ran, test names, numbers) — read X-34's or
  X-35/X-36/X-40's TASKS.md entries to match voice/format before
  writing the next one.
- Every `$$...$$` KaTeX block in any `explain.md` must stay on one
  line — Prettier corrupts multi-line ones (project memory:
  `project_prettier_multiline_katex_corruption`).
- The browser pane in the desktop app doesn't composite frames
  reliably — use Playwright for any rendered-frame proof, not the
  built-in browser tool (project memory:
  `project_browser_pane_no_compositing`).
- If an unrelated e2e test breaks after a fix, don't assume it's
  flaky — bisect it (a `git worktree` against the pre-session baseline,
  bisected forward commit by commit — see commit `ff451c9` and X-36's
  TASKS.md addendum for the exact method used last time this came up).
- Don't fix things opportunistically outside the current X-id's scope
  — log a new X-* entry instead (next free id is **X-61**).
- Stop and ask the user before: any change to `src/modules/types.ts`,
  any binding palette-token change (the angular-colour ΔE proposal from
  audit §8), or anything not already covered by the three decisions
  above.
- **Push discipline:** commit locally after each verified fix so no
  work is ever lost, but do NOT push to `origin/main` without an
  explicit go-ahead from the user in that session — the brief for this
  whole effort defaults to "don't push," and only a direct "commit and
  push" request at a session boundary lifts that, one time. If you
  reach your own natural stopping point, update this handoff doc,
  commit it, and stop without pushing, same as this session did.
