  `[12/sqrt2, 6, 6]` (still speed 12): it needs a vertical component under

  wanted, the alternative is a module-level fallback, not a `types.ts`
  change.

## Things I found that the next session should know

- **The M3-G gate e2e had been passing for the wrong reason.** Its Space
  press landed on the focused "Exit predict mode" button (X-36), time never
  advanced, and the time-series plot appeared only because the series used
  to append a duplicate point per store change (the X-59 flood bug). Fixing
  the series exposed it; the test now clicks Play and asserts `t` advanced.
  Worth remembering when a "flaky"-looking e2e fails right after a fix to
  the thing it depends on.
- **Reading a WebGL canvas in an on-demand-rendering viewport is unreliable
  when the scene is idle** (the drawing buffer is only readable in the frame
  that rendered it; an idle scene reads blank, intermittently). The X-55 test
  originally sampled via `drawImage` in a rAF and was flaky; it now reads a
  canvas **screenshot** (`locator.screenshot()` decoded in-page), which is
  deterministic. Use that for any settled-scene pixel proof.
- **Playwright's fake clock keeps running in real time unless frozen.** For
  tests that depend on a short timer window (X-55's 150 ms fade, X-59's
  420 ms lock), use `page.clock.install({ time: 0 })` and then
  `page.clock.pauseAt((await page.evaluate(() => Date.now())) + 1000)`
  after the page has settled; otherwise Playwright's own actions can finish
  the window on a loaded machine. (X-50's test uses an un-frozen fake clock
  and is stable because it only needs a long fast-forward.)
- **Pixel-count e2e proofs** share one helper, `countMatchingPixels` in
  `tests/e2e/smoke.spec.ts` (colour tolerance, optional clip rect, optional
  `invert`). A fragment-only URL change still needs `page.reload()` before
  the second measurement (ADR 0020's lesson). Choose line widths with the
  1.6x projector multiplier in mind: a 2 px line was too close to sub-pixel
  to measure, so several widths are 3 px.
- **Python on this Windows box defaults to cp1252** for text I/O. Any
  scripted edit of a repo file must pass `encoding='utf-8', newline=''`, or
  inserted non-ASCII characters (em dashes) get written as invalid UTF-8.
  Prefer the `Edit` tool for small changes.
